# seti-tools

Technosignature and biosignature searches on public astronomical archives: the code, the papers, and a database of what
every run searched and found.

| Path | Contents |
|------|----------|
| `seti.py` | the command line: `python -I seti.py <family> <approach> <mode>`, `store <command>` and `selftest` |
| `setitools/` | `core.py` (configuration, network, archive clients, light curves, the coverage store and its vet codes), `science.py` (rest frames, spectral and radio searches, trends, photometry), `catalogues.py` (the readers of the catalogues several approaches share, the epochs of their positions and the moved-position null) and the thirteen family modules, each approach's docstring giving its data, detection rule and modes |
| `coverage.db` | SQLite: one row per run, one per target recorded; its columns are defined in `setitools/core.py` |
| `LEDGER.md` | every approach with its data and its result after vetting, the approaches queued, and the findings about natural objects, instruments and catalogues with the run behind each |
| `RESULTS.md` | every approach of the ledger with its runs, each run's sample in its own unit, and the ledger's result |
| `papers/` | the papers, their sources and the data behind their numbers |

Python 3.11+ with `requirements.txt` (torch for the GPU paths only). `python -I seti.py selftest` checks the package, every
docstring of it one line, and runs the sky-fibre, Kepler glint and meteor-stream detectors end to end on synthetic data with
injected signals, hard negatives and pure noise; `python -I seti.py <family>` lists a family's approaches; `python -I seti.py store card <target>`
lists every run that covered a target, `store table` regenerates `RESULTS.md` from the ledger and the store, and
`store verify` checks the two against each other.

## Configuration

Paths and resource caps come from the environment variables `SETI_DATA`, `SETI_WORK`, `SETI_CACHE`, `SETI_RESULTS` and
`SETI_COVERAGE`, else from a config file outside the repository (the file `SETITOOLS_CONFIG` names, else
`setitools/config.json` under `%APPDATA%` or `~/.config`), else from defaults inside the repository. The file's keys:

```json
{
  "data": "/data/seti",
  "work": "/data/seti/work",
  "cache": "/data/seti_cache",
  "results": "/data/seti/results",
  "coverage": "coverage.db",
  "max_procs": 8,
  "max_connections": 32,
  "contact": "mailto:archive-contact@example.org"
}
```

`data` holds bulk downloads, `work` scratch files, `cache` Breakthrough Listen indexes and chunks, `results` each
search's output files and `coverage` the store; `max_procs` and `max_connections` cap everything one machine runs at
once, and `contact` is added to the user agent every request carries, so that an archive's operators can reach whoever
runs the searches.

A new approach starts with a literature search on its data set and signature. One that repeats published work on the
same data is dropped; otherwise the approach, data, prior work and decision go into `LEDGER.md` before any
download, and the targets are a stated slice (a distance limit, a class of star, a geometric condition), never a whole
archive.

Downloads go to `core.DATA`, Breakthrough Listen chunks to `core.CACHE`, and TESS and Kepler light curves come from
STScI's AWS mirror (`setitools.core`). One machine's worker processes and open connections stay within
`core.MAX_PROCS` and `core.MAX_CONNECTIONS`; GPU work runs through torch with CUDA; a streaming search takes a share
of the target list (`--list`) and the shares merge in its `report` mode.

Reusable code is the `setitools` package: archive clients, HTTP and TAP access, frames, the spectral, radio and
time-series tests, photometry, light curves, the shared catalogue readers and the coverage store. Approaches live in the
thirteen family modules of `setitools/`, run through the one entry point `python -I seti.py <family> <approach> <mode>`
(`seti.py` alone lists the families, a family alone its approaches, `--help` an approach's method and modes); each
approach's docstring (`<approach>_DOC`) is its method, its modes run from `fetch` to `record`, and a new check or
injection test becomes another mode. An approach whose modes are its analysis and `record` declares every threshold as a
keyword of its main function, and `core.run_cli` offers each as an option (`--name value`) with the keyword's default,
so the same test runs on another catalogue cut or tolerance without a change to the code. Outputs go under
`core.RESULTS`, and each approach has a recipe under Recipes below.

A finished run calls `core.record_search` once (archive, release, selection as ADQL or `core.ids_selection`,
the script, which is hashed, thresholds, null, sensitivity, the sample's size and
unit, the result files it reads, and the row of the ledger's Searched table it belongs to) and
`core.record_targets` with one row per target: a prefixed identifier (`gaia_dr3:`, `hip:`, `kic:`, `koi:`, `tic:`,
`apogee:`, `mpc:`, a Breakthrough Listen file and channel, or the survey's own identifier where Gaia DR3 has none,
such as `galah:` and `vlotss:`), followed by `#` and a facet where a run tests one target
several ways (`planet:WASP-121 b#HARPS`, `planet:GJ 486 b#SPIRou HeI`), the statistic, a p-value or limit, and the explanation that
removed a detection, which is stored as codes of `setitools/core.py` (listed under Vetting below) with its words in the
note; an explanation with no code is refused, as is an identifier that stands for a missing one (`gaia_dr3:-1`,
`star:--`). The store holds no archive data; `core.covered(target, approach)`
answers before a download, `python -I seti.py store card <target>` lists one target's results, `table` writes
`RESULTS.md`, and `verify` checks the store against the ledger and the vet codes and for identifiers that stand for missing ones.

## Methods

| Method | Implementation |
|---|---|
| Narrow lines | each spectrum divided by a model that cannot hold an unresolved line (median over visits, non-negative fit of similar stars, or envelope), then a matched filter against a local error (`setitools.science`); a peak must be unresolved and smooth |
| Rest frames | `science.line_tracks` maps a line at rest in the CMB, Solar System, stellar or planetary frame to the telescope; a feature fixed in the star's frame is the star's, one fixed in the observatory's is Earth's or the instrument's |
| Radio tracks | `science.track_search` sums power along the predicted, zero-drift and shifted (null) tracks; ON scans stacked, OFF scans summed along the ON track |
| Trends | `science.differential_trend`: Theil-Sen slope against comparison stars on the same plates, per series |
| Band templates | `biosignatures.band_template`: each gas a set of Gaussian bands at its strongest features, averaged over each bin, fitted with an offset per spectrum; a gas counts by how much the fit worsens without it, so overlapping bands cannot share one feature |
| Nulls | fixed before looking (absorption-like peaks, shifted tracks, random wavelengths, control apertures, comparison stars); a detection must beat the strongest null of its kind, and a recurring group counts as its second-strongest member |

## Archives

Clients are in `setitools/core.py`. TAP services are named in `setitools/core.py` and queried with
`core.tap(service, adql)`, or `core.tap_async` for long scans; `core.tap` sends MAXREC, because the Gaia archive and
SIMBAD stop synchronous results at 50000 rows without saying so (Data Lab excepted, where MAXREC overrides LIMIT), and
raises on maintenance pages. CDS's file tree serves curl's user agent and challenges a browser's.

## Vetting

A candidate must beat its search's null and then survive the explanations below; a survivor gets a literature and
catalogue check of the star and its field. Each explanation is a filter in code. The coverage store's vet column holds
the codes listed at the end (`setitools/core.py`), one or more for each row a filter removed, and the words of the
run's record in the row's note; a row with no vet has no explanation, and `python -I seti.py store verify` fails
on any vet that is not a code.

| Data | Explanations |
|---|---|
| Spectra | sky and telluric lines, and residuals where other epochs' tellurics lie; detector gaps, order joins, arm ends, SPHEREx detector edges; cosmic rays, sharper than the instrumental profile; light in the sky fibre (SOPHIE); fibre persistence (GALAH); corrupt coadd exposures; neighbouring-fibre defects (LAMOST); peaks one or two pixels wide where the instrumental profile spans six (LAMOST); vacuum wavelengths read as air (ESPRESSO); calibration frames filed as science (HST); aperture-fixed features (IUE); ultraviolet spectra crowded with natural lines (supergiants, giants, T Tauri stars, LBVs, Ap stars); twin-model mismatch in broad lines and rare spectra; ionized-metal blends that vary between stars; lines three or more stars share; profiles wider than the instrument's; epochs or stars at the wrong velocity; line depths that change between epochs (slit spectrographs); one exposure reduced twice (ESO); steady features in stars whose epochs share one night, where the star's frame is the instrument's |
| Attribution | catalogue positions of an earlier epoch; pointings off the star (FUSE); one file fetched for both members of a wide pair |
| Radio | zero-drift carriers; interference near 1420 MHz; carriers and their sidebands recurring on one drift in other targets' pointings of the session (sidelobe transmitters); coarse-channel roll-off; known transmitters (`setitools.science.OCCUPIED_MHZ`); satellite navigation and the Galaxy's sidereal swing (e-Callisto); HF leakage and spacecraft lines (Wind, STEREO); bursts in busy bands or at scan edges; spectral-window ends and channel-wide offsets (ALMA) |
| Photon timing | MAMA double counts, COS lamp flashes, hot spots, gain sag; Chandra dither and frame sidebands; flare red noise |
| Photometry | plate steps and proper-motion blends (DASCH); single-transit outliers and close pairs (Gaia); spotted rotators; folds of one or two events; duplicate ALCDEF sessions; binaries and pulsators at KOI periods; timing variations, short catalogue durations and detrending gaps (exobelts) |
| Catalogues | wrong 2MASS matches; chance radio alignments; background galaxies; spurious parallaxes; embedded young stars; silicate bands missing from asteroid templates; X-ray sources SIMBAD files at their X-ray position, 5-15 arcsec from a Gaia counterpart whose own entry carries no type |

## Recipes

### Catalogue checks

| Approach | Data and rule | Run |
|---|---|---|
| Millimetre flares on inactive stars | SPT-3G flare stars without a 2RXS source, crossed with eRASS1, 4XMM, CSC and SIMBAD; a star with no X-ray source is judged against eRASS1's reach at its distance | `seti.py highenergy mm check\|record` |
| Radar reflectors | the PDS SBN radar compilation; a metal reflector has OC albedo near 1 and SC/OC near 0; albedos above 0.3 read with their SBDB classes | `seti.py solar_system radar_albedo` |

### Short-lived elements

Technetium (4.2 Myr), promethium (17.7 yr) and the actinides Pa, Pu, Am and Cm have no natural source in a
main-sequence star. Each star's spectra are put on one barycentric air-wavelength grid, normalised by
`science.envelope`, median-stacked and moved to rest with `science.line_velocity`; stacks need pixel scatter under 10
per cent and a comparison stack correlating above 0.9. `science.line_absorption` fits the six most similar stacks with
the line core left out, `science.combined_line_score` weights the lines by lambda^2 gf exp(-E_low/kT) at 5800 K against
400 random wavelengths, and `combined_line_threshold` gives each star's limit, which injection checks. Lines: Tc I from
Palmeri et al. (2005), Pm II from Fivet et al. (2007), the actinides from NIST with arc intensities for gf; Korg turns
equivalent widths into abundances. The runs are `seti.py composition elements census`, `fetch INSTRUMENT`,
`search INSTRUMENT [ELEMENT ...]` (`--inject STAR EW_mA`) and `record`.

### Laser lines in stellar spectra

Spectra are normalised by `science.envelope` on one grid per instrument. Stars with several visits use
`science.visit_recurrence`, which keeps lines recurring at one stellar-frame wavelength across visits at different
observatory velocities; steady lines use `science.twin_model` and `science.matched_filter`. A peak keeps a width ratio
of 0.6-1.6 against `science.lsf_sigma_px` and a smooth profile, then faces the absorption-like null and
the Vetting section above.
